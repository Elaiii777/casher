# Финансовый трекер

Мобильный финансовый трекер на React + Vite + Tailwind CSS. Главная, единый календарь событий, бюджет дома с редактируемыми категориями, обязательства (долги) с историей платежей.

## Структура проекта

```
finance-tracker/
├── index.html              точка входа, подключает шрифты Manrope/Inter
├── package.json
├── vite.config.js
├── tailwind.config.js
├── postcss.config.js
├── .gitignore
└── src/
    ├── main.jsx             монтирует React-приложение
    ├── App.jsx               вся логика и экраны приложения
    └── index.css             Tailwind + анимации
```

Всё приложение — один компонент `App.jsx` (Главная / Календарь / Бюджет дома / Обязательства + модалки добавления доходов, расходов, категорий бюджета и платежей по обязательствам). Данные хранятся в `localStorage` браузера — бэкенда нет, каждый экземпляр в браузере видит только свои данные.

## Финансовая модель

Четыре независимые сущности, которые не смешиваются между собой:

- **Баланс** (`startingBalance` + фактические записи) — меняется только от дохода со статусом «получено», фактических расходов и фактических платежей по обязательствам.
- **Доходы** (`incomes`) — дата, источник, план/факт сумма, статус (`expected` / `received` / `cancelled`). Планируемый доход в баланс не попадает.
- **Бюджет дома** (`familyBudget`) — категории с месячным лимитом; «потрачено» считается автоматически из расходов, у которых указана привязка к категории.
- **Обязательства** (`obligations`) — долги/платежи с общей суммой, выплаченной частью, датой и суммой очередного платежа. Само обязательство баланс не трогает — только добавленный платёж (`history`).

«Свободные деньги» на главном экране = баланс + ожидаемый доход этого месяца − неоплаченная часть обязательств этого месяца − неизрасходованный остаток бюджета дома.

## Запуск локально

Нужен Node.js 18+.

```bash
npm install
npm run dev
```

Откроется адрес вида `http://localhost:5173`.

## Сборка для продакшена

```bash
npm run build
```

Соберёт статические файлы в папку `dist/` — HTML, JS, CSS, шрифты не нужны отдельно (подключены через Google Fonts CDN). Эту папку можно разместить на любом статическом хостинге.

Проверить сборку локально:

```bash
npm run preview
```

## Деплой

Приложение — обычный статический сайт после сборки, вариантов размещения несколько:

- **Vercel / Netlify** — подключить репозиторий, команда сборки `npm run build`, папка публикации `dist`. Настройки определятся автоматически (Vite поддерживается из коробки).
- **Свой сервер (nginx)** — скопировать содержимое `dist/` в корень сайта, например `/var/www/finance-tracker`, и отдавать как статику. Пример конфига nginx:

  ```nginx
  server {
      listen 80;
      server_name your-domain.com;
      root /var/www/finance-tracker;
      index index.html;
      location / {
          try_files $uri $uri/ /index.html;
      }
  }
  ```

- **GitHub Pages / любой S3-подобный хостинг** — просто загрузить содержимое `dist/`.

## Важно про данные

Сейчас данные (операции, долги) хранятся в `localStorage` — это удобно для одного человека на одном устройстве, но:
- при очистке кэша браузера данные пропадут;
- между устройствами данные не синхронизируются;
- при желании перенести на бэкенд — нужно заменить функции `loadFromStorage`/`saveToStorage` в начале `src/App.jsx` на запросы к своему API.

При первом запуске, если в `localStorage` ничего нет, приложение подставляет тестовые данные за сентябрь 2026 (из исходного сценария). Их можно удалить через интерфейс или через кнопку «Сбросить данные прототипа» на экране «План» — она просто перезаписывает эти же тестовые значения, для реального использования эту кнопку можно убрать или изменить на очистку (пустые массивы).

## Превращение в Telegram Mini App

Когда дойдёт очередь до Mini App, потребуется:
1. Подключить Telegram WebApp SDK (`window.Telegram.WebApp.ready()`, `expand()`), взять цвета из `themeParams`.
2. Заменить `localStorage` на бэкенд с привязкой к `initData` пользователя Telegram — иначе данные не переживут разные сессии WebView.
3. Использовать `MainButton`/`BackButton` из Telegram SDK вместо плавающей кнопки «+».
4. Опционально — бот с напоминаниями о платежах через Bot API.

Дизайн и вся логика расчётов (безопасный остаток, прогноз, долги) переносятся без изменений — меняется только слой хранения и интеграция с Telegram.
